## Reading Flow

Atlas contains Show structure on page / Hide structure on page alongside Start Guided Read. They are secondary task actions under USE THIS MAP, rather than separate product entries. It reveals the document's structural reading path directly on the source page. The session-only layer uses at most seven original cited anchors, preferring validated Page Map `focusPath` and otherwise `nodes`; it neither assigns a heading's role to neighbouring prose nor synthesises missing roles. Exact kind aliases map conservatively to CONTEXT, CLAIM, EVIDENCE, EXAMPLE, COUNTERPOINT and CONCLUSION; other kinds stay KEY PASSAGE. Numbers indicate overlay source order. Entry into Guided Read from a Flow marker was deliberately omitted to preserve its existing state model.

The existing refreshGuide promise/cache handles every request. Successful empty results and results with focusPath but no section nodes now remain in the frontend cache, preventing repeated analysis and allowing valid path-only annotations. Worker schemas and validation are unchanged. Failure keeps local Atlas navigation and exposes a retryable status; zero useful structure creates no markers.

One removable shell layer draws restrained warm source edges and shallow washes without modifying original text, style or source classes. Buttons have concise accessible role/label names, native keyboard activation and source navigation; focus emphasises the cited passage. The nearest represented section on the existing sampled Spine receives a subtle cue. Existing scroll/resize animation-frame scheduling positions the layer; no extra reading listeners or observers are added. Off/exit removes the layer and its button handlers, clears Spine state and cancels pending activation. Source rebuild/root replacement uses existing invalidation; path/search route invalidation also removes Flow immediately. Hash navigation retains it. Reactivation leaves it off; nothing persists across reload.

Labels prefer free source margins using existing bounded host point checks. Narrow or occupied margins use 22px numbered chips. Tall sources use their visible portion, with up to five bounded vertical checks to move below sticky chrome; blocked/offscreen annotations hide. For fragmented column passages only the first visible fragment is treated, avoiding a wash across column gaps. Colliding labels within the small Flow set hide rather than stack into cards. Reduced motion disables the reveal transition.

Visual compromises: compact labels show numbers while their full role remains accessible/title text; zero-margin pages may have a small chip at the text edge. Sparse AI paths can leave long stretches unannotated. First citation/visible fragment is used rather than painting every cited block/column fragment. Geometry is heuristic; nested scrollers, extreme sticky overlays, host transforms and all CSS collisions remain unverified. Source-ID validity proves navigation, not semantic correctness of the returned role. Context green and Critical purple retain their meanings; Flow uses the existing warm Atlas accent. No new Lens, rail action, panel, provider request, persistence, chat or unrelated tool was added.

## Product hierarchy

The product is framed around Navigate, Understand and Examine. The persistent viewport-right rail still has two controls: Atlas and Lens. Atlas says Navigate and contains the restrained secondary structure and Guided Read actions. Lens presents vertical Understand / Context while reading and Examine / Questions worth considering choices. Understand uses a light green filled choice and star; Examine uses a purple outline and diamond. Context remains immediate ambient help, while Critical requires deliberate opening of its question. Guided Read follows Atlas's existing Page Map cache or pending promise, with no fifth request type. Its Follow Atlas controls retain Previous/Next, progress, real-passage spotlight, Stop, return to Atlas, Escape and resume. Explain temporarily takes detail priority without destroying the sequence. With Guided Read active, Flow keeps its cached path, sequence markers and source navigation, but drops its wash and current Spine shadow and fades its borders/buttons. Stop restores Flow emphasis without another request.

Guided Read now offers Explain this passage only for a live step. It supplies that mapped source's text, Source ID and nearby context to the existing selected-text Explain function, request token, provider path, validation, card and Trail. No synthetic browser selection or separate explanation cache is created. Close/Escape from the completed explanation returns to the same step and focuses its Explain action; Back to passage additionally navigates to the real source. Pending and completed Guided Explain survive scrolling. Step changes, Stop, leaving for another detail, Escape during loading, exit and source rebuild cancel pending Guided Explain. Provider failure exposes a retry within Guided Read without losing progress. Selected-text Explain retains its independent entry and scroll dismissal; both explanation entries now share the UNDERSTAND · EXPLAIN result heading and green accent.

Atlas, Lens choices, Guided controls and Explain share bounded adaptive placement. Article/root bounds protect surrounding prose where margins exist; limited viewport point checks avoid occupied sidebars and sticky/fixed host UI when choosing margins. Atlas's inline adaptive width is no longer overridden by CSS; long outlines retain all headings and independent scroll. Narrow or tall full-width passages use compact Guided controls. Source ticks try both edges, hide when both are occupied and track the visible edge of a tall source. Panel scrolling does not chain to the host page. Compact Trace details also clamp their actual width to the rail boundary before height measurement, fixing a 320px overflow. There is no body-wide geometry scan, extra observer, host layout rewrite or website-specific rule.

Atlas remains deterministic navigation: every local heading and its level/order/label is available immediately, before a provider response. Weak-heading pages retain local passage anchors. AI adds section roles or explicitly inferred ranges and guided choices. Failure leaves original headings and local navigation intact; AI is required for generated guided choices and Lens/Explain output.

Context clarifies concepts, terms and background. Selecting it closes the chooser and adds subtle green source-edge ticks, with no global Context findings rail or forced overview. Hover or keyboard focus immediately shows the comprehension aid without a heavy passage outline. Click opens a source-linked detail. Reopening Lens offers optional Browse context and Turn off Lens. Critical uses purple markers, a pause-to-examine hover cue and a click to open the actual open-ended question. Its overview explicitly describes interpretation of supplied passages, not fact checking. Both retain independent caches and support zero results.

## Selection and discovery

After mouse selection completes, a small D / Explain / dismiss action appears near the live selected Range. Keyboard selection still uses the existing selectionchange path. The native selection is preserved when focusing or clicking the local action; there is no custom cursor, global mousemove processing or new observer. A subtle connector and short reduced-motion-aware reveal relate it to the source. Ready, hover/focus, loading, error/retry and success retain explicit states; success replaces the action with the existing card and Trail. Repeated same-selection notifications cannot reset loading or issue a duplicate request. An explicitly dismissed unchanged selection stays dismissed.

Placement tests all Range fragments against candidate boxes. It tries the endpoint and whole-range above/below gaps, then a 14px D source-edge fallback for long/full-width selections. A few bounded point checks avoid neighbouring host text and fixed/sticky chrome; selected Range fragments remain the strict non-overlap gate. A fully occupied viewport can hide the action; this geometric fallback is less discoverable and has a small mouse target, though its button keeps the full accessible name and keyboard focus. Original selected text is never deliberately covered. Other reading panels retain their existing bounded-overlap compromises.

Close, Escape, dismiss and Back to passage restore selected-source focus. A temporary tabindex is kept until blur so browser focus remains on a normally nonfocusable paragraph, then restored; exit/rebuild also cleans it. Existing host tabindex values are preserved. Scroll dismisses, resize remeasures the cloned live Range, and source rebuild/exit removes scheduled layout and cancels pending responses through the existing token. Payload, Source ID, nearby context, validation and request type are unchanged.

One temporary hint appears on first activation in the content-script page session, naming Atlas → Navigate, Lens → Understand / Examine and Select text → Explain. It expires after eight seconds, pauses while focused, supports dismiss/Escape, and disappears when Atlas/Lens/selection actions open or on exit. It never steals focus, sends AI or writes storage. Reactivation does not repeat it; reload starts a new page session.

## Dormant / active lifecycle

Before activation: load script definitions and CSS, create one tiny D launcher, register its click handler and the existing runtime toggle listener. No Source Map, Atlas/Lens/Guided UI, reading observers, scroll/resize/selection handlers, Explain or AI request.

First activation: create reading UI once, build Source Map/local Atlas, attach named reading handlers, a scoped content MutationObserver, shallow ancestor replacement observer and Atlas IntersectionObserver. Activation alone sends no AI request. The one-time temporary reading-actions hint is shown here.

Exit: make controls inert; close details; remove Lens ticks, guided state/spotlight and selection/Explain UI; cancel late Explain via request token; remove reading handlers; disconnect all reading observers; cancel scheduled dynamic/layout work. Existing safe Page Map/Lens caches remain in memory. Already sent requests may finish and cache their result, but cannot reveal dormant reading UI or restart reading observers.

Reactivation: compare path/search and validate connected elements, normalized source text and heading levels within the cached reading region. This skips body-wide scoring/coverage when unchanged. Otherwise perform a full build and invalidate caches only if map identity actually changes. A pending meaningful edit forces full checking. Repeated activation cannot duplicate UI or listeners.

## Invalidation and diagnostics

- Observe text/child changes only within the chosen reading region and its readable open/nested shadow roots. Body fallback necessarily has a wider scope.
- Shallow child-list observation on ancestors catches disconnected/replaced article/main/host roots. Unrelated sibling updates do not trigger a map build.
- Meaningful text edits, readable additions/removals and heading/visibility/slot attributes schedule one 900 ms debounced check. Whitespace-only changes in ordinary prose are ignored; whitespace within preformatted code is meaningful. Shrinking a mapped generic block still invalidates it. A genuine rebuild also dismisses the pending selected-text request so a late Explain cannot attach its old source ID to a changed map.
- Class/style changes, excluded page UI, buttons, clocks and explicit live status/timer regions are ignored during active observation. Numerical prose and table values remain meaningful.
- Hash-only navigation retains caches. Popstate path/search changes request validation. SPA pushState changes accompanied by substantive content/root replacement are caught by content observers; history APIs are not monkey-patched.
- Coverage selection and extraction thresholds are unchanged. Source IDs, deduplication, composed order and real element anchors remain. Open-root inventory is now scoped to the reading region.
- Explicit developer call `DeepReadDebug.snapshot()` in the content-script execution context returns aggregate build/validation durations and counts, source count, coverage estimate, fallback reason, active/observer state, observed shadow-root count and last rebuild reason. It emits no automatic logs and includes no page text/title/URL/key.

## Five biggest remaining weaknesses

1. Real Chrome injection, worker lifetime, extension reload, host CSS/SPA integration and real cross-site responsiveness remain unverified.
2. Extraction/coverage are heuristics. Initial scoring still traverses safe body content; very large regions and body fallback may be expensive. Coverage 1 is an estimate, not semantic completeness. Class/style-only visibility changes and a newly attached shadow root without an observable content change may be missed while active. New useful siblings outside an unchanged selected region wait for another full build.
3. Gemini sees at most 36 sampled blocks of 700 characters. Valid citations prove anchors exist, not correct roles, representative guided choices or useful questions. Current Lens differentiation was exercised with mocks, not a broad real-model quality sample.
4. The selected action hides when no safe Range-adjacent position fits; its compact D is less discoverable and offers a small mouse target. When no unoccupied margin or vertical gap fits, other bounded details can still cover text on wide articles, very narrow/short windows, tall passages, columns or sticky overlays. Compact Guided controls reduce this overlap; they cannot eliminate it. Point checks sample a few positions rather than proving the whole panel area is clear; pseudo-elements, transformed host containers, nested scroll areas and host chrome outside the samples remain risks. Trace details and hover previews retain their earlier placement logic. Existing Explain input limits still truncate passages beyond 3600 characters at the worker; no model/schema limit changed.
5. Real screen-reader/high-zoom acceptance, production credential protection and durable state are absent. The ignored local key is still accessible to someone with the extension build. Trail/caches are session-local; closed shadow roots, canvas/WebGL and inaccessible cross-origin frames remain unsupported.
